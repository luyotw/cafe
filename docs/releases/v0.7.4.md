# CAFE v0.7.4 release notes

## Release scope

CAFE v0.7.4 is a patch release containing the runtime and release-check
performance improvements from #593, plus a repository ignore rule for
`.DS_Store` files. It preserves the public CLI, workflow declarations, and
acceptance contracts shipped in v0.7.3.

## YAML and skill metadata performance

Production YAML readers use LibYAML's `CSafeLoader` when available and fall back
to PyYAML's Python `SafeLoader`. Both paths retain safe construction; custom
locale and callback loaders continue enforcing their existing validation.

Skill discovery rereads each file's frontmatter and reuses parsing by exact
header content. The cache holds at most 128 headers, each no larger than 32 KiB;
larger headers bypass it. Returned metadata is deep-copied, so one caller's
edits do not change another caller's view. File edits and project overrides
remain visible without relying on path or timestamp freshness.

The kickoff catalog fingerprint includes the YAML helper, so helper changes
invalidate the catalog through the existing dependency mechanism.

## Release-check performance and reports

Kickoff tests use isolated global catalogs rather than depending on locally
installed skills. Coverage and extended kickoff tests use work-stealing
scheduling, with eight and four workers respectively by default. All previous
regression case identities remain covered; this release adds 16 regression
cases for safe parsing, metadata freshness, and failed-run reporting.

On the same development machine, the full release gate decreased from 519.91
seconds for v0.7.3 to 129.74 seconds for the reviewed performance commit, about
75% less elapsed time. These are local release-check measurements; application
speed and test duration depend on workload, machine resources, and cache state.

```bash
# Lower concurrency on machines with fewer resources.
CAFE_TEST_WORKERS=4 CAFE_EXTENDED_TEST_WORKERS=2 ./scripts/release-check.sh

# Run both test stages serially.
CAFE_TEST_WORKERS=0 CAFE_EXTENDED_TEST_WORKERS=0 ./scripts/release-check.sh

# Choose a report root.
CAFE_TEST_REPORT_DIR=/tmp/cafe-release-reports ./scripts/release-check.sh
```

Each invocation writes test logs, JUnit reports, and `timings.json` into a
separate `release-check.*` directory under `.cafe/reports` by default.
`release-check-latest.json` records the latest finished run. Timing records
include coverage, extended kickoff tests, contracts, lint, build, installation,
and package checks, with exit status retained for failures.

The release gate still validates built-in contracts, builds the wheel and source
distribution, installs the wheel in a clean environment, and checks packaged
commands, playbooks, and runtime constraints.

## Upgrade guidance

```bash
pip install --upgrade cafe-engine==0.7.4
```

No additional migration is required from v0.7.3. Its
[upgrade guidance](v0.7.3.md#upgrade-guidance) remains applicable: Gemini,
Copilot, and Cursor phase chat use one-shot `--prompt` because their interactive
adapters cannot deliver the required initial constraints context.

Publishing the GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
