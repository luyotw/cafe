# CAFE v0.9.1 release notes

## Release scope

This patch includes all develop changes through `a081b257`: delegated
subagent-flow delivery result confirmation, separate Manager closeout authority,
clearer kickoff contracts and the phase-default composition cleanup (#439,
#626). Cost accounting, pricing, delivery verification and Slack destinations
from v0.9.0 remain included.

## Delivery acceptance and closeout

The bundled subagent-flow playbook permits the Manager to confirm delivery
results when the user-confirmed task assignment delegates that decision.
Integration action permission remains mandatory and user-owned. Completing or
proxy-confirming a result does not authorize cleanup.

New full kickoff contracts store Manager closeout separately, with an explicit
cleanup, archive, leave or pending choice. After verified delivery completion
and worker quiescence, the Manager can execute the exact user-confirmed choice
without asking again. A pending choice, changed commands, changed targets or
invalid evidence requires user selection or reconfirmation before execution.

Older combined delivery tasks and recorded results retain their original schema
and evidence. An explicit user-submitted terminal choice remains usable; a
Manager proxy or historical completion without recorded user authority cannot
supply a cleanup or leave decision. Successful integration is preserved while
missing terminal authority is resolved separately. Adopting the split contract
uses normal user reconfirmation and task supersession, preserving prior receipts.

See [development delivery](../development-delivery.md) for the workflow boundary.

## Kickoff clarity and phase defaults

Kickoff contracts describe delivery and Manager cleanup responsibilities in
plain language, show preference changes by their behavior and preserve delegated
confirmation settings. Unusable saved preferences stay out of the user-facing
proposal rather than appearing as unexplained implementation details.

Development playbooks now reuse validated defaults declared by their primary
phase skills. Mapping overrides merge recursively; lists, scalar values and
explicit null replace defaults. Invalid defaults are rejected even if an
explicit override would hide them. Multiple selected skills must produce
matching effective step contracts. Compatibility baselines and public callers
verify resolved behavior and project overrides. Graph-dependent PR feedback
hooks and publication authority remain explicit in playbooks so defaults do
not impose an undeclared target or capability on existing custom steps.
Delivery reads bounded task-binding projections instead of Manager private
contracts; terminal effects still require the verified Manager contract.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved version update also synchronizes and verifies the four bundled
CLI-native helper skills from the newly installed package. Existing workflows
retain their confirmed contracts; adopting changed delivery or closeout facts
requires user reconfirmation rather than silently rewriting authority.

The release gate checks coverage, extended kickoff journeys, strict skill and
playbook contracts, critical lint, wheel and source builds, a clean installation,
a real v0.9.0 upgrade with pending PR and delivery tasks and persisted cost
evidence, and v0.7.5 legacy continuation with duplicate-completion protection.
No paid model requests are needed for these checks.

Publishing the GitHub Release triggers the trusted PyPI publisher for the exact
v0.9.1 tag.
