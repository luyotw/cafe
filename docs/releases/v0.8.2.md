# CAFE v0.8.2 release notes

## Release scope

This patch release ships Codex App-owned Manager callback delivery (#612) and
workspace-boundary/local test performance improvements (#618) on the v0.8.1
baseline. Cost accounting and pricing remain on develop. New delivery planning
and verification contracts (#617) and named Slack destinations (#619) are
outside this patch release.

## Codex App-owned Manager callbacks

A separate configured daemon can see an App-owned Manager thread as unloaded
and reject resume because that exact thread already has an active writer. CAFE
recognizes only the exact native rejection and submits the callback through the
shared native queue. The owning host retains dispatch, FIFO and user-stop
behavior; CAFE keeps the original Manager session.

Before launching background work, CAFE checks the bound thread, confirmed model
and queue API without adding input. A failure before queue admission is
conclusively nonaccepted; a lost or corrupt admission acknowledgement remains
ambiguous and requires the existing recovery path. Restarting does not replay
an ambiguous event or route it to a replacement session. Configured daemon
recovery from v0.8.1 remains available.

## Workspace and local test performance

Workspace verification batches root and commit resolution and reuses only an
exact snapshot verified within the same leased execution boundary. Every guard
still observes fresh Git state; correction dispatch retains both fresh checks.
Cached workflow tests strictly validate each requested builtin playbook and
continue resolving project and global overrides on each load.

Local commit and push hooks keep their existing test selections and use four
work-stealing workers. Set `CAFE_TEST_WORKERS=0` for serial execution or another
non-negative integer to adjust concurrency. Hooks report their slowest tests;
release gates retain their separate configured worker defaults.

## Upgrade guidance

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

Approved CAFE updates also synchronize and verify the four bundled CLI-native
helper skills from the newly installed package. Existing workflow graphs,
HumanTasks, delivery approvals and session continuation require no migration.
The release gate checks a clean wheel installation, an actual v0.8.1 pending
delivery review and a legacy v0.7.5 PR task with duplicate-result protection.

The native callback transport requires supported experimental Codex queue and
turn-history APIs. An unsupported bound session fails preflight visibly rather
than silently switching sessions or expanding authority.

Publishing the GitHub Release triggers the trusted PyPI publisher for the exact
v0.8.2 tag.
