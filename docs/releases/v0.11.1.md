# CAFE v0.11.1 release notes

## Release scope

This patch includes the develop fixes through `c85ed783`: original interruption
handoff recovery, saved delivery checkpoint recovery, removal of obsolete
iteration repair, and corrected delivery/cleanup instructions.

## Recovery fixes

Ordinary workflow entry reconnects an unfinished original interruption
preparation before user-wait routing or provider execution. It restores the
same pending HumanTask and stops for its owner; it does not answer the task,
retry the provider or reset a budget. Advancement and workspace leases prevent
concurrent recovery from taking over an active execution.
Already-published pending handoffs retain normal legacy task-upgrade behavior;
a second host worker cannot reuse another invocation's advancement ownership.

The delivery consumer can restore an omitted checkpoint from one complete
checkpoint retained in the producing iteration. Original session, execution
context, authority, current content, endpoint and required independent review
must still validate. Conflicting, stale or ambiguous evidence retains the
existing correction or human route rather than inventing success.

## Repair operation changes

The obsolete `cafe repair --kind iteration` operation is removed. Inspection
never rewrites iteration state. Standalone `--kind readiness` is also removed;
use the workflow's existing authorized execution entry to validate and recover
its saved checkpoint. These removed selections return refusal, not a successful
repair. Explicit `interruption` and `pr-result` repair remain available with
their original evidence and authority requirements.

Existing workflow sessions, pending decisions, completion receipts and cost
records retain their identities. No manual state deletion or budget reset is
required for this upgrade.

## Delivery and cleanup fixes

Development delivery instructions require integration into the confirmed base
branch, locally or through GitHub, with verification of the actual integration
result. Local artifacts alone do not complete development delivery. The runtime
continues to read already-confirmed local-only contracts.

New default closeout proposals archive the CAFE record, remove its managed
worktree and local branch, and include selected remote-branch removal. A lighter
cleanup requires an explicit user choice. Existing authority and confirmation
requirements still apply; these instructions do not grant merge or cleanup
permission independently of the confirmed contract.

## Verification and upgrade

The final-commit release gate covers coverage and extended kickoff journeys,
strict contracts, critical lint, distributions, a clean wheel installation,
packaged authoring/accounting/effort/repair checks and workflow upgrades.
Controlled local evidence does not claim a new live provider acceptance run.

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved update synchronizes bundled CLI-native helpers from the installed
release. Publishing the GitHub Release triggers trusted PyPI publication of
the exact v0.11.1 tag.
