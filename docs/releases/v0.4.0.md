# CAFE v0.4.0 release notes

## Release scope

CAFE v0.4.0 makes workflow composition modular without moving topology or
authority into phase skills. Injected workflow skills can now contribute their
own execution contract and checklist gates, while the runtime composes one
source-aware effective contract for the step. The release also improves Driver
progress reporting, targeted settings updates, artifact evidence, and closeout.

Existing workflow state remains readable. Driver contracts using schema v3 or
v4 require explicit user reconfirmation before they can gain v5 Driver
authority; they are never silently upgraded.

## Versioning and roadmap

CAFE now uses release numbers to describe change impact rather than roadmap
cycles. A backward-compatible user-visible capability increments minor, while a
fix-only release increments patch. Roadmap stages remain product-direction
markers and no longer reserve release numbers. See the
[versioning policy](../versioning.md) for the complete rules and the path to
1.0 stability.

## Effective contracts and checklist overlays

Shared, role, and step-injected workflow skills can contribute required tools,
prompt inputs, HumanTask policies, execution profiles, and checklist overlays.
Contributions retain their source identity, resolve local references from the
declaring skill, and fail with source-specific diagnostics when declarations
conflict.

Checklist overlays select independently from the primary phase checklist and
append in deterministic injection order. Their Todo projections use distinct
consumer-local handles, participate in the same completion and recovery gates,
and are revalidated against current source content and Git evidence before a
successful handoff. Existing playbooks without overlays keep their established
behavior and checklist format.

The new `direct-subagent-review` playbook uses this composition model to add
focused detail and scope reviews to Develop without duplicating the Develop
skill. The new `direct-qa` path provides independent review and QA for work whose
requirements are already clear enough to skip a separate plan.

## Topology-neutral routing and durable evidence

Phase instructions now return semantic outcomes while playbooks and runtime
route those outcomes to concrete steps. Runtime-generated route catalogs cover
ordinary success, correction, self-loop, and terminal paths without requiring a
phase skill to name its neighbors.

Workspace companions bind human-readable artifacts to a verified repository,
base and head commit, changed-file set, and clean worktree. Todo and correction
flows preserve producer identity across retries and overlays. Verification
receipts remain available when explicit command provenance is useful, but are
no longer required for ordinary Todo completion.

## Driver operation and closeout

Every user-visible Driver reply now includes a generated, locale-aware progress
diagram showing the latest phase states, review and confirmation checkpoints,
correction returns, and delivery or cleanup status. The renderer reads durable
state and is strictly presentation-only.

`cafe settings update` can preview or save one supported workflow-scoped change
to the Driver configuration or `pr.auto_create`. Existing Driver contract v3
and v4 documents retain their schema, identity, and original confirmation
provenance; saving a setting does not resume work or perform publication.

Kickoff now presents the complete localized contract and exact repository-derived
deliver and cleanup command arrays. After completion, the Driver asks whether to
run the confirmed cleanup, archive workflow state only with
`cafe close --archive-only`, or leave external state unchanged. Callback,
session, retry, and terminal-completion handling have also been hardened to
avoid replaying consumed work.

Supervising users can use `cafe task complete --handoff-to <phase>` to override
the declared continuation after providing a valid task result. The target must
be a phase in the owning playbook, and the override is retained in the task
result. `assignee_type: hybrid` is now deprecated; model new ownership
boundaries as explicit top-level steps and see the
[hybrid workflow migration guide](../hybrid-workflow-migration.md).

## Upgrade

1. Finish or checkpoint any workflow that is currently executing before
   replacing the installed version. When resuming an issue whose Driver
   contract uses schema v3 or v4, review the current proposal and explicitly
   reconfirm it so CAFE can atomically replace it with a v5 contract. Legacy
   contracts cannot grant ordinary Driver-entry or task-decision authority.
2. Install v0.4.0 from the canonical GitHub release. Runtime update checks and
   approved installs now use that release identity rather than PyPI.
3. Run `cafe audit` and `cafe skill validate --strict` in customized projects.
4. Run `cafe skill sync-global` if bundled helper skills should replace the
   currently managed global copies.

Custom injected skills may adopt `workflow.checklist_overlay` incrementally.
Their ordinary primary `workflow.checklist` is not implicitly activated as an
overlay, and existing playbooks do not require conversion.
