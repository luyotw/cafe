# CAFE v0.6.0 release notes

## Release scope

CAFE v0.6.0 adds reusable preparation inputs for Manager kickoff and a shared
workflow conversation-language contract. It also improves recoverability at
artifact and workspace completion boundaries. The release includes changes
merged into `develop` after v0.5.1, including issues #565, #573, #574, #576,
#579, and #582.

## Kickoff preparation

New private user and repository preferences can prefill applicable kickoff
choices without replacing the issue's confirmed contract. An effective-playbook
index and source-checked delivery and model evidence can be reused while their
inputs remain valid. A staged helper supplies editable, typed drafts to the
existing complete kickoff formatter and exposes missing decisions. Model
capability evidence remains separate from live availability checks. Exact
delivery targets, confirmation, and action authority still come from the
current issue.

The functional changes in #573 were verified, but its original end-to-end
performance acceptance was not met. The final comparable observation recorded
257.255 seconds against a 240.226-second baseline, with remaining repeated
reads and incomplete comparative coverage. This release does not claim a
measured kickoff speedup. The preserved measurement record is in
[`docs/benchmarks/issue573-kickoff.md`](../benchmarks/issue573-kickoff.md).

## Workflow language and Manager role

New workflows resolve and store one conversation locale at creation. Supported
HumanTask presentation and notifications use English or Traditional Chinese,
with documented English fallback where no authored translation exists. A locale
change affects subsequently created work; pending task choices retain their
saved presentation and canonical answers. Existing workflows without a stored
locale remain readable through the English fallback without rewriting state.

The active workflow role is named Manager. Existing Driver workflows keep their
selected legacy authority and can continue through the compatibility path;
they are not silently converted into new Manager contracts. Maintained
instructions and callbacks use the current primary Manager session.

## Completion and recovery

Correctable artifact-format failures and dirty-workspace completions return to
the producing session within a bounded correction budget. Delivery rechecks
current workspace and publication evidence before hooks and result-consuming
steps; interruption and exhaustion retain durable recovery evidence. The
release also supports explicit workflow user handoffs, bounded retries for
incomplete provider streams, and fixes to progress presentation and empty PR
feedback handling.

## Upgrade guidance

1. Install the published package:

   ```bash
   pip install --upgrade cafe-engine==0.6.0
   ```

2. Keep existing pending HumanTasks and legacy Driver authority records intact.
   A new workflow records its resolved locale; an existing workflow without one
   continues using the documented fallback. Use the explicit workflow-language
   change command when a stored workflow locale must change.
3. Review saved kickoff preferences before relying on them in a new proposal.
   They supply defaults and evidence, not confirmation or external-action
   authority. Existing global helper installations require the deliberate
   helper-sync path to receive updated instructions.

Publishing the GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
