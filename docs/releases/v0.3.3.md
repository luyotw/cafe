# CAFE v0.3.3 release notes

## Release scope

CAFE v0.3.3 makes workflow execution more durable and more explicit about who
may decide, execute, and publish each action. It adds event-driven Driver
hosting, a repository task inbox, registered host capabilities, transactional
catalog synchronization, QA-oriented playbooks, and safer recovery from
interrupted agent sessions.

This release also contains two compatibility changes: the built-in `default`
playbook ID is replaced by `standard`, and the `cafe operation` command is
removed.

## Event-driven workflow Drivers

Workflow Drivers can now run through a durable, event-driven contract. CAFE
persists Driver identity and policy, launches bounded workflow workers, reports
status, and delivers workflow events back to the originating agent session.
Callbacks remain observational and cannot answer mandatory user tasks, expand
authority, or silently change the configured model chain.

One-shot `cafe chat <role> -p` prompts let a Driver consult a phase agent without
entering an interactive terminal session. Playbook-aware delivery contracts
also make closeout responsibilities explicit instead of assuming that every
workflow ends by publishing a pull request.

## Human tasks and trusted host capabilities

The new task inbox provides stable commands to list, inspect, complete, and
cancel durable HumanTasks. Responses are correlated with their workflow and
wait state so stale or duplicated completion attempts fail closed.

Host-side effects now pass through typed capability manifests, policy
evaluation, optional approval, revalidation, and durable receipts. GitHub PR
publication, issue comments, browser opening, and Slack HumanTask notifications
use the same registered boundary. Workflow-managed scripts run through explicit
lifecycle trust and sandbox contracts rather than inheriting ambient authority.

## QA playbooks and review convergence

The built-in playbook catalog now includes `standard-qa` and `tdd-qa`, backed by
a shared QA role, the `cafe-qa` acceptance skill, and durable `qa_feedback`.
Failed acceptance routes through bounded development, review, and QA loops
before publication. A direct reviewed workflow and explicit applicability
metadata improve playbook selection for work that does not fit the default
software-delivery path.

Review guidance is split into focused phase resources for preflight, risk
assessment, correction, acceptance closure, and finalization. Correction loops
now include convergence safeguards rather than repeating unchanged feedback
indefinitely.

## Recovery and concurrency safety

Agent interruptions pause for a durable HumanTask instead of treating partial
output as completion. Users may retry the same provider session or explicitly
start a fresh session while preserving phase, iteration, model, authority, and
the previous session identity. Existing pending interruption tasks can adopt
the additive fresh-session choice safely.

Workflow state, HumanTasks, notifications, capability attempts, and terminal
handoffs now use stronger atomic update and replay protection. Provider errors
including incomplete streams, temporary overload, permissions, quotas, and
timeouts retain more accurate classifications and do not grant a trustworthy
handoff by themselves.

## Catalogs, helpers, and updates

Project and global agents, skills, and playbooks resolve through a consistent
catalog precedence model. Synchronization is transactional, bounded, and
content-addressed, with crash-safe migration and symlink handling. Global
helper publication no longer happens from Git hooks and will not overwrite an
existing managed copy implicitly; use `cafe skill sync-global` when an update
is intended.

Runtime updates require an explicit approval boundary and validate the selected
release before replacing the installed launcher.

## Upgrade

Before upgrading an existing project:

1. Replace `playbook: default` with `playbook: standard` in project and active
   issue configuration. There is no compatibility alias.
2. Replace automation that calls `cafe operation` with repository-owned Git
   hooks or CI. Keep verification receipts only where the playbook declares a
   receipt contract.
3. Run `cafe audit` and `cafe skill validate --strict` after installation.
4. Run `cafe skill sync-global` explicitly if the bundled helper skills should
   replace the currently managed global copies.

The persisted HumanTask format remains readable, and pending interruption tasks
can be upgraded in place when inspected. As with any release that changes active
workflow execution, finish or checkpoint long-running work before upgrading.
