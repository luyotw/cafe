# CAFE v0.9.2 release notes

## Release scope

This patch fixes the missing provider-native independent reviewer integrations
in streamlined workflows. It includes the implementation reviewed in #631 and
preserves the delivery, closeout, pricing and cost accounting behavior from
v0.9.1. No new CLI commands or workflow declaration formats are introduced.

## Native independent review

Gemini, Copilot and Cursor now receive invocation-local native reviewer
definitions with read-only tools or permissions. CAFE binds actual native child
completion to the current checkpoint, approved reviewer identity, configured
model and independent conclusion before runtime and delivery validation.
Temporary definitions are removed after each physical execution; existing
agents, authentication and resumed native sessions remain available.

Gemini accepts completed GOAL progress containing the independent child result.
Copilot requires the matching native start, confirmed actual model, completion
and successful tool result. Cursor accepts a synchronous Task success and its
final child assistant message. Cursor plugin reviewers inherit the parent
model; independent model overrides are rejected explicitly.

Codex 0.159.3 inherits live parent permissions even when a role file requests
read-only access. Its spawn/wait observer therefore accepts only explicitly
read-only, verifiable API-key parents and verifies the actual child model and
read-only journal context. Writable development parents, unverified
ChatGPT/cloud requirements and unsupported permission profiles remain blocked.
CAFE never substitutes a separate CLI reviewer session.

Malformed, cancelled, failed or contradictory terminal results cannot satisfy
review or delivery. The first invocation checkpoint and observation time are
preserved; identical completion replay, including repeated Codex wait polling,
is accepted. Structured response parsing now retains native observations,
including the existing Claude integration.

See [streamlined CLI contracts](../cli.md) for the native provider versions,
model behavior and completion evidence checked by this patch.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved version update synchronizes and verifies the bundled CLI-native
helper skills from the newly installed package. Existing workflow authority and
recorded completion evidence retain their original contracts.

Two independent subagent reviews approved the implementation with zero blocking
findings. Automated tests exercise native-schema parent transport, checkpoint
and delivery validation, model and permission mismatches, cancellation and
contradictory event replay. Installed native metadata loaders were checked
without paid model requests; those checks do not claim a live model workflow.

The release gate checks coverage, extended kickoff journeys, strict contracts,
critical lint, builds, a clean wheel installation, and persisted legacy and
v0.9.0 workflow state after upgrade. Publishing the GitHub Release triggers the
trusted PyPI publisher for the exact v0.9.2 tag.
