# CAFE v0.5.1 release notes

## Release scope

CAFE v0.5.1 fixes workflow progress presentation and clarifies primary Driver
callback ownership. It also reduces test execution costs. This patch retains
the v0.5.0 persisted workflow format.

## Workflow progress fixes

The progress renderer reads execution history from the canonical `audit_events`
store. A completed draft waiting for clarification or permission now appears as
waiting for a response, while phases that have not started remain pending.
Iteration timestamps provide progress evidence even when `status_code` is absent.

The user-facing diagram retains confirmation ownership labels and ends with
the deliver and cleanup items. Task-routing and authority diagnostics remain
available through task inspection.

## Primary Driver guidance

Event-driven callbacks target the current primary Driver. Choosing a different
CLI or model for a phase agent does not transfer Driver ownership or silently
start another Driver conversation.

## Test performance

Focused workflow tests reuse immutable builtin skill metadata. Formatter checks
reuse the real CLI entry point in the test process, with subprocess coverage
retained for CLI and environment boundaries. AST checks avoid repeated traversal.
All existing parameter combinations and assertions are retained.

A local comparison of the same 349 tests reduced runtime from 124.2 seconds to
64.4 seconds.

## Installation

Install the published package:

```bash
pip install --upgrade cafe-engine==0.5.1
```

Existing global helper installations use the explicitly approved helper-sync
path. Ordinary status and show commands do not replace installed helpers.

Publishing this GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
