# CAFE v0.5.0 release notes

## Release scope

CAFE v0.5.0 makes issue split guidance optional for custom playbooks, keeps
workflow audit history and capability receipts outside the blackboard, and
improves current-state inspection and Driver task completion. This minor release
changes persisted workflow state and removes the `cafe summary` alias.

## Issue split guidance

Playbooks can enable `behavior.allow_issue_decomposition` globally or override it
for an individual step. Built-in playbooks enable the behavior; an omitted value
in a custom playbook resolves to false. Guidance applies to any enabled step,
including playbooks without spec, plan, or PR phases.

Agents propose separate issues for independently deliverable outcomes using a
short title, scope, and dependency list. Tightly coupled work stays together
without a decomposition report. The behavior adds no scoring, evidence fields,
new artifacts, or confirmation gates. Phase agents recommend splits; only the
Driver uses the existing authorized path to create issues.

## Workflow state and status

`blackboard.json` now contains current workflow state and references instead of
embedded audit events or capability receipts. Full audit records live under
`audit_events/`, and capability receipts live in `capability_receipts.json`.
Callback identity, delivery, and replay use those separate authoritative stores.

`cafe status` presents the current phase, pending HumanTask and its inspection
command, pause reason, completion state, timeline, and usage. It reads existing
callback failure diagnostics through a declared diagnostic source without
delivering callbacks or resuming the workflow. Missing or conflicting state is
reported as unknown. Ordinary status reads avoid loading unrelated audit bodies.
Workflow progress rendering also remains available when a pending task cannot
be resolved; it retains the confirmed contract's ownership labels.

## Driver and recovery

HumanTask routing and resolution ownership are evaluated separately. A
Driver-confirmable task can be completed from its confirmed contract and current
inspection, with authority rechecked at the durable completion boundary.
User-required confirmations, mandatory stops, permissions, and capabilities
remain with the user.

Callback continuation survives transport changes and contract reconfirmation.
Delivery failure explanations include an actionable recovery direction. A failed
checklist validation exposes the existing retry path, and completed checklists
can retain reviewer annotations. PR delivery defaults to merge commits rather
than squash.

## Upgrade guidance

1. Finish active workflows using their original installed CAFE version before
   upgrading. v0.5.0 does not migrate older prepared or persisted workflows; do
   not resume them with this release. Retain archived workflow files for history,
   and start fresh workflows after upgrading.
2. Install v0.5.0 from the
   [GitHub release](https://github.com/luyotw/cafe/releases/tag/v0.5.0) or PyPI:

   ```bash
   pip install --upgrade cafe-engine==0.5.0
   ```

3. Replace `cafe summary` commands with `cafe status`.
4. To enable split proposals in a custom playbook, declare
   `behavior.allow_issue_decomposition: true` at playbook or step level. Leave it
   omitted or false when the playbook should not propose splits.
5. Run `cafe audit` and `cafe skill validate --strict` in customized projects.
   Use `cafe skill sync-global` deliberately to update existing global helpers;
   ordinary inspection does not overwrite them.

Publishing this GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
