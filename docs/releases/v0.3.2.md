# CAFE v0.3.2 release notes

## Release scope

CAFE v0.3.2 is a documentation-only patch release that gives new users a
clearer explanation of what CAFE does, why it is useful, and how to begin using
it through a supported CLI agent. It does not change runtime behavior, workflow
schemas, or persisted state.

## A clearer introduction to CAFE

The README now introduces CAFE through its core idea and three primary benefits:

- moving complex, multi-step work from clarification through delivery;
- letting agents work autonomously while people retain key decisions; and
- preserving workflow state so work can resume, move between agents, and become
  a reusable playbook.

The handoff example shows how Codex can continue from persisted workflow state
when Claude reaches its usage limit, without restarting the task or requiring
the user to restate its requirements.

## Agent-guided onboarding

The primary user journey no longer assumes that the user wants to operate CAFE
through terminal commands. Installation, workflow kickoff, status inspection,
recovery, and customization are expressed as natural-language requests that a
CLI agent can carry out on the user's behalf.

Advanced implementation details remain available for users who need to author
custom phases or playbooks, diagnose workflow behavior, or inspect CAFE's
security and authority boundaries.

## Upgrade

No workflow-state migration is required. Existing v0.3.1 installations do not
need to upgrade for runtime fixes; v0.3.2 packages the revised README and release
metadata with the current CAFE runtime.
