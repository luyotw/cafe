# CAFE v0.10.0 release notes

## Release scope

This minor release adds schema-driven phase/playbook authoring (#551, #638)
and scoped Codex native subagent usage in workflow cost reports (#630).
It retains v0.9.3's ChatGPT authentication and explicit Codex permission modes,
existing provider integrations and confirmed delivery/cleanup authority.

## Phase and playbook authoring

Use version-1 YAML/JSON requests to create or patch writable source contracts:

```bash
cafe playbook author --spec pair.yaml --dry-run --format json
cafe playbook author --spec pair.yaml --apply --expect-change <change_digest> --format json
cafe skill author phase --spec phase.yaml --dry-run --format json
```

`--spec -` accepts stdin. Select exactly one of `--dry-run` and `--apply`;
`--format json` emits one machine-readable result. The library provides
`prepare`, `apply`, `decode_request` and `request_schema` through `cafe.authoring`.

Preview constructs canonical phase structure and validates runtime contracts,
effective dependencies, affected consumers, artifact routing, confirmation
gates and graph simulation without executing authored hooks or agents. Apply
checks the reviewed digest and source state before confined staged publication,
with rollback and interrupted-transaction recovery. Unrelated catalog edits
do not invalidate an otherwise unchanged candidate; changed used sources do.
Focused patches preserve untouched bytes and uniform line endings.

Authors still supply procedures, artifacts, routing and permission decisions.
Authoring does not confirm a workflow or grant execution/publication authority.
See [Source contract authoring](../authoring.md) for an executable paired request,
supported operations, diagnostics and transaction limits.

## Codex subagent usage and cost

Explicitly admitted worker, correction, chat and Manager intervals now collect
direct and nested Codex native descendant usage from bounded, read-only local
journal evidence. Records preserve session ownership, actual model, invocation
boundaries, verified resume/fork baselines and final or partial coverage.
The supported local format is Codex CLI 0.159.3; unsupported or ambiguous
evidence remains incomplete instead of inventing counters or prices.

Shared admission reconciles caller and child records before reporting tokens
and costs, rejecting duplicate replay, overlapping physical ranges and
unverified parent inclusion. Cached input and reasoning are subsets, not extra
tokens to add to the total. Accounting failures do not change provider results,
retry selection or process exit status. Abrupt termination retains an open
incomplete checkpoint; it does not guarantee collection of unavailable child
totals.

New compatibility usage scalars represent the caller; descendant evidence
remains in the existing `cost_records` envelope and reports. Readers preserve
valid historical child-inclusive data and independently evidenced legacy
amounts without rewriting history or repricing old records. Missing coverage
remains distinct from a verified zero. Manager-inclusive reports retain their
existing human preference and cleanup boundaries.

This release collects supported local native evidence; it does not add live
Codex App Server notification ingestion or expand delegation authority. See
[Cost accounting](../cost-accounting.md) for source bounds and reconciliation.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved version update synchronizes and verifies bundled CLI-native helper
skills from the installed release. Existing workflow contracts, pending PR and
delivery tasks and historical cost evidence retain their original authority.
Existing workflows do not need conversion to authoring requests.

The final-commit release gate checks coverage, extended kickoff journeys,
strict contracts, critical lint, distributions, clean wheel installation and
persisted legacy/v0.9.0 workflow state after upgrade. Package smoke checks also
exercise authoring preview/apply and the installed native accounting helpers.
Native accounting regressions use sanitized local evidence; they do not claim
new paid-model or live App Server usage-ingestion verification. Publishing the
GitHub Release triggers trusted PyPI publication for the exact v0.10.0 tag.
