# CAFE v0.4.1 release notes

## Release scope

CAFE v0.4.1 fixes interrupted Driver closeout and Claude event-driven session
bootstrap. It also adds a trusted publishing workflow for PyPI. No workflow
contract migration is required.

## Durable closeout outcomes

Confirmed `deliver` and `cleanup` commands now run through a helper that records
their exact arguments and outcomes in the repository's shared Git directory.
The record survives issue worktree removal. After an interruption, the Driver
can inspect it without replaying a command whose outcome is succeeded, failed,
or unknown. A failed or unknown outcome still needs an explicit recovery
decision. Confirmed closeout plans are size-limited so their complete evidence
can be persisted.

## Claude event-driven Driver

Claude's empty-scope command no longer receives extra tool or MCP configuration
flags, which previously prevented the session bootstrap from starting. When the
Driver contract leaves the model unpinned, CAFE now accepts the provider's
reported default model when validating the new session. An explicitly pinned
model must still match.

## Publishing and upgrade

Publishing the GitHub release triggers a trusted GitHub Actions workflow that
builds the tagged source and publishes `cafe-engine` to PyPI. The workflow uses
short-lived OIDC credentials rather than a package token.

Install v0.4.1 from the [GitHub release](https://github.com/luyotw/cafe/releases/tag/v0.4.1)
or from PyPI after publication. Existing v0.4.0 workflow state remains readable;
run `cafe audit` and `cafe skill validate --strict` in customized projects after
upgrading.
