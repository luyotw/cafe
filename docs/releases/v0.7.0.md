# CAFE v0.7.0 release notes

## Release scope

CAFE v0.7.0 adds a unified workflow Manager conversation entrypoint and native
read-only phase diagnosis. The release integrates the conversation transport
(#489), Manager chat (#465), and read-only chat (#520), plus post-v0.6.0 kickoff,
callback, and provider-output fixes from both `main` and `develop`.

## Talk to the current Manager

From a prepared issue worktree:

```bash
cafe manager chat
```

From the repository checkout, select the intended live issue explicitly:

```bash
cafe manager chat --issue <issue-name>
```

The terminal accepts one message per line; `/quit`, EOF, and Ctrl-C exit. Opening
chat submits no request and changes no workflow position, baton, or HumanTask.
Each submitted turn reconnects to the exact current supported identity, refreshes
durable workflow context, and verifies the reply. Chat does not grant additional
permission or answer a mandatory or user-owned task.

This release supports verified event-driven, provider-owned Codex primary
sessions and the already-active confirmed Codex fallback. Host-bound Codex
threads, other providers, attached/unattended modes, legacy/unverifiable
records, and missing sessions receive explicit guidance to return to the
originating Manager. Chat does not create replacement sessions, switch providers,
or replay an uncertain delivery. See [Manager chat](../manager-chat.md) for the
full support and recovery matrix.

`cafe manager chat` is separate from `cafe chat <phase-role>`; a custom phase role
named `manager` retains its original meaning. The installed `cafe` entrypoint
uses the Manager-owned CLI composition. Source users can invoke
`python -m cafe.manager.cli`; `python -m cafe.ui.cli` remains the generic
compatibility entrypoint without Manager commands.

## Read-only diagnostic chat

Use an authorized phase-agent consultation with the issue's configured provider,
model, phase, and existing conversation context:

```bash
cafe chat developer --phase develop --read-only
cafe chat developer --phase develop --read-only -p "Explain the current failure and propose one bounded next action."
```

Codex, Claude, Gemini, Cursor, and Copilot receive their native restrictions for
interactive and one-shot diagnosis. CAFE skips helper synchronization, handoff
preparation, session/timestamp updates, usage publication, catalog/state repair,
and Gemini ignore-file preparation. Existing artifacts, HumanTasks, results,
baton, blackboard, and linked/shared CAFE context remain unchanged. Eligible
stale-session recovery retains the restrictions and provider/model; any recovered
session is kept only in memory. Native-option and backend errors remain errors,
with no writable retry or automatic provider change.

These options do **not** provide immutable confinement of the whole provider
process. Provider-owned history/configuration, native UI commands, mutable
permissions, integrations, subprocesses, and IPC may still write. The README
records a Claude native-shell bypass observation, mutable Codex settings, and
Gemini plan-file/mode-transition limitations. Cursor and Copilot whole-process
mutation denial has not been demonstrated. See [Read-only diagnostic chat](../../README.md#read-only-diagnostic-chat)
for native options and the precise verification limits. Manager chat does not
add this phase-chat flag or become a read-only diagnostic session.

## Transport and recovery

Phase chat, Manager chat, and event callbacks share an internal transport backed
by the existing provider strategies. Provider identity, model, acceptance, and
usage evidence remain distinct from workflow authority. Callers continue to own
locks, persistence, fallback, ambiguous-delivery recovery, and user decisions.
See [Conversation transport](../conversation-transport.md) for the contract.

Provider stdout and stderr are drained concurrently to avoid backpressure and
buffered acknowledgement delays. Failures retain bounded, safe diagnostic
summaries; native-option rejection remains actionable without echoing raw
provider content. Bound Codex host callbacks validate their transport before
submission. Existing user-selected fresh-session recovery can recover a failed
new session even when it has not yet returned an identity.

Noninteractive Codex calls also observe verified native SSE and WebSocket
activity when stdout is quiet. The idle timeout remains 300 seconds, explicit
duration/output budgets still apply, and transport activity does not establish
completion. Invocation-only telemetry uses a temporary loopback receiver and
retains metadata without prompt text or streamed deltas. Existing telemetry
exporters are preserved: initialization fails rather than replacing an effective
export destination. Ignored user configuration and selected-profile exporter
precedence follow the native CLI. See [Codex stream activity](../codex-stream-activity.md)
for the adapter contract and validation scope.

Kickoff confirmation now explicitly distinguishes using the proposed project
preferences once from remembering applicable defaults. Preferences remain inputs,
not permission or automatic confirmation.

## Upgrade guidance

1. Install the published package:

   ```bash
   pip install --upgrade cafe-engine==0.7.0
   ```

2. Preserve existing workflow state, pending HumanTasks, Manager identities, and
   legacy Driver authority. This release requires no new workflow-state migration
   and does not silently convert unsupported identities into supported ones.
3. Use the deliberate helper-sync path for existing global helper installations
   so diagnostic guidance receives `--read-only`. Existing confirmation,
   task ownership, and external-action authority remain unchanged.
4. Check the Manager support matrix and native read-only limitations before
   relying on a new conversation or diagnosis path.

Publishing the GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
