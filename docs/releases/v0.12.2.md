# CAFE v0.12.2 release notes

## Namespaced issues

CAFE preserves the full issue identifier, such as `team/fix-login`, through
Manager launch and confirmation, detached worker handoff, and workflow event
callbacks. PR publication and delivery use the same issue identity to find
the issue record and its worktree.

## Workflow recovery

When a delivery recovery task returns to development, the feedback and its
linked To-dos stay available to the development agent. If correction
preparation fails before the provider starts, an approved fresh-session retry
can prepare the first context packet and continue from the saved feedback.
Correction feedback follows the latest handoff, and relative source paths
resolve from the issue's project root even when the command runs elsewhere.

## Worktree cleanup

`cafe close` resolves bases such as `origin/develop` to the destination branch
when it verifies integration before cleanup.

## Codex usage accounting

Forked sessions can carry copies of their parent's active turns. Accounting
excludes copied turn events when the source journal confirms their ownership
before the fork. Fork journal headers with the source session ID remain useful
for discovery. Missing or unverified usage still appears as a coverage gap.
