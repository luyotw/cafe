# CAFE v0.9.3 release notes

## Release scope

This patch fixes Codex streamlined execution with ChatGPT CLI authentication
and development commands that were blocked by the previous native review
permission contract. It includes the changes reviewed in #634. Other providers,
delivery endpoints, cleanup authority, pricing and cost accounting retain their
existing behavior. No new CLI commands are introduced.

## ChatGPT-authenticated native review

Codex uses one authenticated native app-server for development, an independent
native review fork and continuation in the original parent session. ChatGPT CLI
login and API-key authentication are both supported; CAFE does not read stored
credentials or require an API key when the CLI is already authenticated.

CAFE verifies the actual parent and fork identities, configured model,
permissions and independent terminal conclusion. Model changes, contradictory
completion, extra delegation and managed feature overrides cannot satisfy
review or delivery. Exact session resume, declared retry budgets, scope
checkpoints and separate per-model token accounting remain in effect.

## Execution without an OS sandbox

New Codex compact proposals explicitly default to
`read_only_enforcement: instruction_only`. Development, native review and the
parent continuation run with `danger-full-access`, without an OS sandbox.
The reviewer remains inspection-only by role instruction and technically
retains write access. Host evidence records that sandboxing is disabled and
the actual parent and reviewer permission policies. Content checkpoints reject
changed reviewed content before delivery; they do not prevent writes or undo
external side effects.

Already confirmed contracts without this setting preserve their original
sandbox permissions. Explicit `read_only_enforcement: sandbox` continues to
use a workspace-write parent and a read-only native fork, requiring a working
native OS sandbox. Resume never silently changes confirmed permissions;
changing an existing contract uses the normal confirmed-contract replacement.

See [streamlined CLI contracts](../cli.md) for provider versions, permission
modes and required native evidence.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved version update synchronizes and verifies the bundled CLI-native
helper skills from the newly installed package. Existing workflow authority
and recorded completion evidence retain their original contracts.

Two independent subagent reviews approved the implementation with zero
blocking findings. The complete implementation regression passed 7,751 tests
with 17 skipped and 84.51% coverage. A ChatGPT-authenticated real model/tool
smoke on Codex 0.159.3 completed development commands, tests, independent native
review, same-parent continuation and delivery readiness in 129.06 seconds.
That owned local fixture did not publish a PR or merge remote changes.

The final-commit release gate checks coverage, extended kickoff journeys,
strict contracts, critical lint, builds, a clean wheel installation and
persisted legacy/v0.9.0 workflow state after upgrade. Publishing the GitHub
Release triggers the trusted PyPI publisher for the exact v0.9.3 tag.
