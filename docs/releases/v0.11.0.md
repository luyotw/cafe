# CAFE v0.11.0 release notes

## Release scope

This minor release includes the confirmed develop snapshot through `40bc1786`:
phase reasoning effort (#408/#641), live project skill exposure (#645/#649),
workspace and saved-evidence recovery (#648/#646), manual startup and progress
fixes (#643), Codex request pricing (#644), and development delivery refinements.
It preserves the authoring and native descendant accounting shipped in v0.10.0.

## Phase reasoning effort

Each CLI/model entry in `.cafe/phases.yaml` may specify `reasoning_effort`.
The Manager chooses the exact model and supported effort together. Retry uses
the same entry, fallback uses its own choice, and exact session resume reapplies
the admitted entry. Native review also validates the reviewer combination.
Missing effort preserves the provider default; null, blank and unsupported
explicit values are rejected rather than silently approximated.

Verified controls are available for supported Codex, Claude and Copilot
combinations. Gemini and Cursor preserve omission but reject explicit effort
until an independent invocation control is verified. Evidence distinguishes
configured, applied and provider-reported values; it does not infer internal
thinking from token counts. See [Phase reasoning effort](../reasoning-effort.md)
for admission, capabilities, cache behavior and future adjustment authority.

## Live project skills

Active valid `.cafe/skills/<name>` sources are exposed to provider-native skill
directories through managed live links. Local edits remain visible without
copy synchronization, while selected workflow/chat skills retain runtime
placeholder rendering. Existing project/global resolution and user-owned
entries are preserved; unsafe roots, conflicting ownership and symlink
traversal are checked before changes.

See [Project skills](../../CONTRIBUTING.md#project-skills-and-native-cli-exposure) for managed-link
ownership, worktree behavior and recovery guidance.

## Saved-evidence and workspace recovery

The new top-level `cafe repair` command previews supported machine-evidence
repairs without running a phase:

```bash
cafe repair --issue example --kind iteration --step build_custom --iteration 1
cafe repair --issue example --kind iteration --step build_custom --iteration 1 --execute
```

Kinds include `iteration`, `interruption`, `readiness` and `pr-result`.
Readiness/PR repair requires the original saved resolved execution context.
Execute checks worker quiescence, existing leases, original identities and
evidence before the exact local repair. It does not answer a HumanTask, change
models or sessions, grant publication authority, reset budgets or replay an
external action. Ambiguous or conflicting state is refused.

Normal recovery preserves workspace authority across CLI/model/session changes
and interrupted publication. Valid saved readiness can pass existing gates
without rerunning providers or hooks. Terminal success now requires the exact
committed completion receipt and validated original artifacts/handoff; receipt
capacity or authentication failures leave execution recoverable. Unknown PR
results are reconciled from original receipts rather than republished.

The bundled workflow driver's diagnosis reference documents repair kinds,
bounds, JSON outcomes and the existing continuation route after repair.

## Delivery, progress and cost

All twelve adopting development playbooks make final result confirmation
assignable. New Manager proposals default to Manager confirmation; users may
retain it. Action permission remains user-owned. Existing confirmed contracts
retain their recorded ownership and require explicit reconfirmation before
adopting changed gate contracts. Verified local-only delivery can be accepted
and left in place using its matching local result.

Manual workflow startup, compact progress, outcome-only chat handoffs and
bounded iteration/correction bookkeeping are corrected. Codex workflow, chat
and descendant costs use verified per-request evidence where available,
including long/short context pricing, while unknown or incomplete evidence
remains explicit. Stored historical costs are not repriced.

See [Development delivery](../development-delivery.md) and
[Cost accounting](../cost-accounting.md) for evidence and authority boundaries.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved update synchronizes and verifies bundled CLI-native helpers from
the installed release. Existing phase entries without effort, pending human
decisions, workflow authority and historical accounting remain readable.
Complete model/effort entries must agree with the confirmed execution context;
changing a setting does not silently replace a confirmed contract.

The final-commit release gate checks coverage, extended kickoff journeys,
strict contracts, critical lint, distributions, clean installation, packaged
authoring/native accounting, effort configuration and repair command surfaces,
plus legacy/current workflow upgrades. These checks use controlled local
evidence and do not claim a new live model/provider acceptance run. Publishing
the GitHub Release triggers trusted PyPI publication for the exact v0.11.0 tag.
