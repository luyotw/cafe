# CAFE v0.12.1 release notes

## Release scope

This patch includes develop fixes through `2845433d`: accurate workflow progress,
completed causal feedback settlement, step-scoped session recovery, known cost
subtotals and evidence coverage, and QA/Manager evidence interpretation (#647/#667).

## Workflow progress and recovery

Reactive task corrections and redirected retries render as returned workflow
phases. Accepted automatic delivery and terminal completion reflect actual saved
decisions and results. Session recovery follows the step being retried instead
of leaking the previous step's session policy into a supervisor redirect.

Proven completed causal feedback can settle across runtime instances without
replaying the provider or rewriting the original artifact. Recovery validates
the original completion, source artifact, transition, checklist and feedback
projection; missing or conflicting proof remains unresolved. Pending decisions,
handoffs, authority and retry budgets retain their existing ownership.

## Cost subtotal and coverage corrections

Progress reports label the amount as a known cost subtotal excluding the Manager.
Previously known amounts remain visible when other evidence is partial. Missing
descendant coverage is distinguished from missing caller usage or pricing; a
complete caller estimate alone cannot certify subagent coverage.

Cache creation/write names are aliases rather than two mandatory counters.
Conflicts remain invalid, and historical alias-only chat flags can be interpreted
only when complete per-call records cover every recorded call.

An empty iteration is not proof that no model ran. Only a bound uninvoked-provider
interruption or the delivery owner's verified host-only receipts can establish
model-free execution. Unknown automatic commands, tools or missing/corrupt
records retain coverage gaps. Interpretation preserves prior calls, chat usage,
legacy amounts and immutable native gaps through archival; historical costs are
not repriced. See [Cost accounting](../cost-accounting.md).

## QA evidence interpretation

QA and the existing Manager review bind conclusions to the affected public entry,
prerequisite state, ordinary payload branches and observed result. Reports record
fixture starting points, substitutes and bypassed boundaries instead of combining
disconnected local passes into a full journey claim. Current-stage acceptance,
deferred product outcomes and pending repository-owned checks remain distinct.

The regression evaluation archive retains original reports, provenance and
reviewed replay inputs. These changes correct evidence interpretation and do not
add a QA pause, alter verification exemptions or authorize unrelated scope.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

An approved update synchronizes bundled CLI-native helpers from the installed
release. Existing confirmed contracts, pending decisions, sessions and historical
accounting remain readable. The delivery-before-close migration from v0.12.0
continues to apply.

The final-commit gate covers coverage, extended kickoff journeys, strict contracts,
lint, distributions, clean installation, packaged profiles and command surfaces,
existing feature checks and workflow upgrades. Controlled local evidence does not
claim a new live provider acceptance run. Publishing the GitHub Release triggers
trusted PyPI publication of the exact v0.12.1 tag.
