# CAFE v0.9.0 release notes

## Release scope

CAFE v0.9.0 adds invocation cost accounting and provider pricing commands (#607),
combined runtime/helper updates (#608, #610), configured Codex daemon recovery
(#611), and delivery correction receipt fixes (#613). The new public pricing
commands and accounting capabilities require a minor release under the versioning
policy. All v0.8.0 workflows and restart contracts remain available.

The unmerged Codex App-owned callback queue work in PR #612 is outside this release.

## Cost accounting and pricing

Costs distinguish provider-reported amounts, token-based estimates, and unavailable
telemetry. Explicit reported zero is retained; missing data is not a confirmed
zero. Each estimate preserves its invocation/model evidence, rates, source,
snapshot version and assumptions. Historical estimates are not recalculated when
rates change. Retry, fallback and resumed-session records retain their individual
usage without charging overlapping or repeated telemetry twice.

Status, timeline, step and workflow views share the same persisted totals and
identify partial coverage. Existing nonzero historical amounts remain visible
with legacy provenance; old default zero values remain unknown.

```bash
cafe pricing status --provider all --json
cafe pricing refresh --provider all --json
```

OpenAI, Copilot, Cursor and Gemini rates have packaged offline snapshots. Automatic
refresh runs in the background after a 24-hour check interval and affects later
invocations; launch and shutdown do not wait for HTTP. Failed refreshes retain the
last valid rates and never stop agent execution. Set `CAFE_PRICING_AUTO_UPDATE=0`
to disable automatic checks; explicit refresh remains available.

Claude retains provider-reported cost. Interactive terminals retain their existing
accounting readers and may have incomplete model/invocation coverage. API-equivalent
estimates do not allocate subscription fees, included credits or account-specific
charges. See [cost accounting](../cost-accounting.md) for provider counter semantics,
rate sources and unsupported paths.

## Version updates include helper skills

An approved `cafe update apply` updates the installed runtime and its bundled
`use-cafe-workflow`, `write-cafe-agent`, `write-cafe-playbook`, and `write-cafe-phase`
helpers. It selects detected CLIs and destinations with existing CAFE helpers,
uses the newly installed bundle, and verifies destination contents. Other user
skills and project catalogs retain their separate publication scope.

Managers completing pip/uv or legacy-updater upgrades synchronize the same helpers
without another skill/CLI approval. User-scoped Python installations are supported
without loading checkout overrides. A helper failure is a partial update and
blocks preparation after the runtime changes; retry only synchronization for the
same installed version and destination scope.

## Configured daemon recovery

Before event-driven launch or callbacks, CAFE probes the configured Codex endpoint.
A stopped or stale endpoint with verified managed-installation ownership permits
one bounded native daemon restart and a second probe. The confirmed Manager session
is preserved. Missing installation evidence and unsafe endpoint replacement remain
explicit recovery cases. This does not bootstrap a first daemon or replace the
callback transport with PR #612's App-owned queue.

## Delivery corrections

A completed host delivery can return through the declared development correction
handoff. Its selected merge/integration/follow-up actions retain their own approval
and receipt validation, without requiring receipts for actions that were never
selected. The exemption applies only when both development delivery hooks are
present; unrelated capabilities retain the existing generic gate. Recorded effects
are not repeated merely because delivery is revised.

## Upgrade guidance

```bash
pip install --upgrade cafe-engine==0.9.0
```

Raw pip installation itself does not publish helper skills. A Manager performing
the upgrade completes the bundled helper step; independent CLI users can run
`cafe skill sync-global` with explicit `--cli` targets from the installed release
outside a source checkout. Existing-helper-only destinations must be included.

Existing workflow graphs, pending HumanTasks, sessions and confirmed delivery
contracts remain authoritative. No manual edits to generated records are required.
The [v0.8.0 upgrade guidance](v0.8.0.md#upgrade-guidance) still applies when upgrading
older workflows. Pricing commands do not rewrite historical usage records.

Publishing this release builds and publishes the exact tagged package through the
existing trusted GitHub-to-PyPI publisher.
