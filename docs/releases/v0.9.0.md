# CAFE v0.9.0 release notes

## Release scope

This minor release ships all develop changes through `d251ca99`, including
provider cost accounting and pricing (#607), Manager cost progress and optional
closeout reports (#621, #623), delivery planning and verification (#617), named
Slack destinations (#619), clearer kickoff scope and verified cleanup defaults.
It includes all fixes shipped in v0.8.2.

## Costs and pricing

Workflow attempts, fallback failures and chat executions retain invocation-level
cost evidence. Summaries distinguish provider-reported USD, token-based
API-equivalent estimates and unavailable cost. Retries, resumed sessions and
copied invocation records are deduplicated; historical amounts are never repriced
when a rate card changes. Unknown coverage is not a zero charge.

Codex, Copilot, Cursor and Gemini use bundled or cached official rate cards;
Claude retains its reported USD cost. Background updates do not block agent
execution. Inspect all four cards without network requests or explicitly refresh:

```bash
cafe pricing status --provider all --json
cafe pricing refresh --provider all --json
```

Set `CAFE_PRICING_AUTO_UPDATE=0` to disable automatic refresh. Estimates exclude
subscription allocation, account discounts and unsupported billing dimensions;
they do not establish an account invoice. Model or usage evidence that cannot
support a calculation remains unavailable. See [cost accounting](../cost-accounting.md)
for provider-specific coverage, cache behavior and manual overrides.

Manager progress shows persisted worker costs excluding Manager usage. After
verified cleanup, the Manager offers an optional report including its own
retained accounting. Reports show known subtotals and partial coverage where
telemetry is missing. Accounting survives feature worktree removal; requesting
a report does not authorize cleanup or another delivery action.

## Delivery planning, permission and verification

The twelve bundled development playbooks now prepare and review PR content
before delivery proposes the exact integration and verification plan. PR content
confirmation does not authorize merging or issue creation. Delivery obtains
mandatory action permission, performs the approved integration and runs the
approved verifier for the actual integrated commit before final acceptance.

The new `cafe.delivery.verify` capability uses an approved self-contained Python
verification tool. The optional GitHub Actions checker belongs to the delivery
skill. Pending checks resume through the background worker without repeated
integration; failed, skipped, missing, wrong-version or unknown checks cannot
reach acceptance. Repository edits needed for a verifier return through the
existing development, review and PR correction path.

### Existing workflows

Persisted pending HumanTasks, restart settings and historical accounting remain
readable. Explicit legacy project catalogs retain their existing correlated
action authority. When adopting the new bundled graph for an existing workflow,
reconfirm any stale stop contract before continuing: PR is a content gate,
delivery action permission remains mandatory, and outcome confirmation stays
separate. An old PR content approval cannot become new delivery permission.
Do not replace an in-flight project override merely to match the latest bundle.

PR corrections retain structured feedback delivery. A HumanTask binding may
explicitly set `mandatory_confirmation: false` to keep its content review
assignable even when it delivers correction feedback. Omitted values retain the
legacy mandatory default for feedback-bearing confirmation gates. This setting
does not change permission-task authority; bundled delivery action permission
and outcome confirmation remain user-owned.

## Slack destinations

Machine-owned `~/.cafe/credentials.yaml` can define a required `default` and
additional named Slack destinations. Private `~/.cafe/config.yaml` routes exact
repository paths to those names; linked worktrees use the parent repository.
Task notifications and Manager callbacks share this resolver.

Existing legacy credentials continue to work when the new store is absent.
An invalid new store fails visibly rather than silently using old credentials.
Credentials are not created or migrated automatically. Follow the
[setup and migration guide](../human-task-slack-notifications.md) to stage a
private store and change routes; do not commit webhook URLs to the repository.

## Kickoff and cleanup

Kickoff describes the estimated implementation footprint using file names for
small changes and modules for larger changes. Default Manager cleanup proposals
archive accepted workflow records and remove the exact verified feature
worktree, local branch and bound remote branch, closing a verified bound issue
when applicable. All effects are shown for confirmation. Explicit preservation
choices remain available; a canonical checkout is never removed. Cleanup checks
source identity, integration and cleanliness before destructive operations.

## Upgrade and verification

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

Approved updates synchronize and verify the four bundled CLI-native helper
skills from the newly installed package. The release gate runs coverage,
extended kickoff journeys, strict contracts, critical lint, distribution builds
and a clean wheel installation. It checks actual v0.8.2 pending delivery state
and historical cost data across the upgrade, plus a v0.7.5 legacy PR continuation
with duplicate-completion protection. Packaged pricing snapshots and the new
delivery verification capability are checked without paid model requests.

Publishing the GitHub Release triggers the trusted PyPI publisher for the exact
v0.9.0 tag.
