# CAFE v0.8.1 release notes

## Release scope

This patch release contains the three approved fixes: bundled helper updates
(#610), configured Codex daemon recovery (#611), and delivery correction receipt
checks (#613). Cost accounting and the pricing command remain on develop and
are not included in this release.

## Bundled helper updates

An approved CAFE version update also synchronizes and verifies the four bundled
CLI-native helpers: use-cafe-workflow, write-cafe-agent, write-cafe-playbook and
write-cafe-phase. Targets include detected coding agents and agents with an
existing CAFE helper installation. A second skill update confirmation is not
required. Helpers come from the newly installed package, even when the update
starts inside a checkout. User-owned skills and project catalogs retain their
separate policies. A helper failure reports partial completion and the command
needed to finish synchronization.

## Configured Codex daemon recovery

Workflow launch and callbacks restore a previously configured, installed Codex
daemon after it stops or its control socket becomes stale. Recovery probes the
resolved endpoint, verifies ownership and installation evidence, starts the
configured daemon with a bounded native command, then checks the endpoint again.
Existing Manager session bindings are retained. This does not bootstrap an
unconfigured daemon, replace an untrusted endpoint, create a new Manager session
or replay an ambiguous callback.

## Delivery corrections

A delivery result that needs code correction can return through development and
review without being blocked by receipts for actions that were not selected.
The delivery executor and outcome hooks retain action-specific approval and
receipt validation. Other capability gates remain active. Existing receipts do
not authorize repeating completed external operations.

## Upgrade guidance

```bash
cafe update check --json
cafe update apply --token <approval-token>
```

The combined-update policy also applies when an agent upgrades CAFE through pip
or uv: it completes helper synchronization from the installed package. Existing
workflow graphs, HumanTasks, session continuation and delivery approvals retain
their original authority. No configuration migration is required. The release
gate checks a clean wheel installation, pending v0.8.0 delivery review state,
and legacy v0.7.5 PR completion with duplicate-result protection.

Publishing the GitHub Release triggers the trusted PyPI publisher for the exact
v0.8.1 tag.
