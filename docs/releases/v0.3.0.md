# CAFE v0.3.0 migration guide

## Release scope

`0.3.0` opens the v0.3 development cycle. The HumanTask, task inbox,
assignment, due-date/SLA, capability-policy, and approval-flow goals assigned
to v0.3 in the roadmap are delivered progressively through `0.3.x`; their
completion criteria are the exit criteria for `0.4.0`.

This guide documents the behavior shipped specifically in `0.3.0`.

CAFE v0.3.0 replaces several compatibility paths with strict workflow
contracts. Finish or archive important v0.2.x workflows before upgrading, and
keep a copy of their `.cafe/issues/<issue>/` directories if they may need to be
inspected later.

## Command migration

Legacy phase commands are no longer available:

```text
cafe spec
cafe plan
cafe develop
cafe review
cafe pr
```

Run the configured playbook with `cafe make`. To start at an explicit step, use:

```bash
cafe workflow --start-step <step> --execute
```

Use `cafe status` instead of `cafe summary` for the workflow timeline.

## Baton migration

`next_step.txt` must contain a JSON handoff contract. Plain step names and
`key=value` content are no longer normalized. Custom integrations must write
the owner, target step, and intent using values declared by the active
playbook, for example:

```json
{
  "version": 1,
  "to_owner": "agent",
  "to_step": "review",
  "intent": "await_agent",
  "message": "Implementation is ready for review."
}
```

Do not resume an unfinished v0.2.x workflow until its baton and artifacts have
been migrated or the workflow has been restarted under v0.3.0.

## Execution configuration migration

Runtime crew and preset configuration has been removed. Do not migrate
`.cafe/crew.yaml`, role-level model maps, or fallback presets into v0.3.0.
Every agent-executed playbook step instead needs one exact ordered CLI/model
chain in the active issue worktree's `.cafe/phases.yaml`:

```yaml
develop:
  name: David
  role: developer
  clis:
    - cli: codex
      model: gpt-5.6-sol
    - cli: claude
      model: claude-opus-5
```

The workflow driver establishes and reassesses these issue-owned chains. CAFE
rejects missing, empty, or malformed chains before invoking an agent.

## HumanTask and ownership migration

New user-owned handoffs are persisted in `human_tasks.json` with a workflow ID,
assignment, wait state, validated result, and lifecycle evidence. Existing
paused handoffs without this file remain usable through the legacy completion
path; they are not retroactively converted into durable tasks. Unknown or
malformed durable-task schemas fail closed.

Custom playbooks may declare user, agent, host, script, automatic, or hybrid
ownership. Validate every ownership transition and HumanTask continuation
before resuming an unfinished custom workflow. Feedback delivered through
development, review, and PR loops is now durable and must follow the declared
feedback-source contract.

## Context packet migration

New built-in spec and plan artifacts must not add packet-specific IDs,
authoritative ID lists, or a model-authored `Downstream Contract`. The complete
Markdown artifact is the semantic authority. CAFE derives structural packet
manifests and plan checkbox records at runtime, then falls back to the complete
source when extraction, persistence, provenance, or integrity validation fails.

Existing valid v1 downstream-contract artifacts remain readable. Custom
playbooks should keep packet eligibility on the declared consuming artifact
edge rather than assuming built-in step or artifact names.

## Custom skill and playbook migration

- Use the namespaced bundled skills such as `cafe-spec`, `cafe-plan`,
  `cafe-develop`, `cafe-review`, and `cafe-pr`.
- Declare prompt inputs, checklist variants, human tasks, hooks, and transitions
  in skill or playbook contracts instead of relying on phase-name behavior.
- Declare an execution profile for agent phase skills so the workflow driver
  can choose and reassess a provider-neutral capability band.
- Migrate interactive prepare configuration to declarative prepare fields.
  Older custom playbooks may still receive a migration warning while the
  presentation adapter is available.
- Validate custom assets before running them:

  ```bash
  cafe playbook validate <playbook>
  cafe skill validate --strict
  ```

## Global helper skills

CAFE now synchronizes bundled workflow helper skills on CLI startup and through
configured Git hooks. Run the explicit command after an upgrade if an installed
copy was manually modified or a startup warning requests repair:

```bash
cafe skill sync-global
```

## Release verification

Source checkouts can run the same gate used for the release artifact:

```bash
./scripts/release-check.sh
```

The gate builds the package and installs the wheel into a clean temporary
environment, so it also detects undeclared runtime dependencies.
