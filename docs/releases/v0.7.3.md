# CAFE v0.7.3 release notes

## Release scope

CAFE v0.7.3 publishes the canonical runtime constraints registry from #493 and
integrates its execution, chat, inspection, documentation, and freshness
contracts. It also fixes recovery before agent invocation, joint planning
without a prior plan, the Python environment used by publishing scripts, and
chat accounting warnings and resumed Codex token totals.
This release combines the completed changes from `main` and `develop` after
v0.7.2.

The `0.7.3` release number follows an explicit user request. Its scope includes
new user-visible inspection commands and declaration capabilities, which would
ordinarily receive a minor increment under the
[versioning policy](../versioning.md).

## Canonical runtime constraints

A package-owned, versioned registry now records existing runtime limitations,
policy boundaries, their applicability, source evidence, mitigation, and
escalation guidance. A typed resolver selects applicable facts from the CLI,
provider, platform, surface, operation, workload, capabilities, consumers, and
explicit opaque mode tags. Opaque modes are propagated through execution,
chat, inspection, and Manager contexts without interpreting them as authority.

Resolved guidance reaches phase execution, retries and fallbacks, workflow chat,
and read-only inspection. The registry supplies existing numeric enforcement
sites for idle, exit-wait, and callback budgets, avoiding separate copies of the
same limits. Bounded rendering and semantic fingerprints track material changes
in existing resume and Manager freshness evidence. External facts with expired
or uncovered verification are presented as unverified rather than enforced as
known numeric limits.

The registry records facts and guidance. It does not authorize worker control,
answer human-owned tasks, grant permissions, or establish completion. Existing
transport, recovery, confirmation, and fallback boundaries remain applicable.

## Inspect and verify constraints

The read-only CLI exposes the registry and scoped views:

```bash
cafe constraints list
cafe constraints show agent.stdout-idle
cafe constraints list --cli codex --platform linux --operation managed --capability long-command --json
cafe constraints list --issue ISSUE --step STEP --json
```

Explicit mode, workload, capability, and consumer selectors can narrow a view.
Issue inspection derives applicable context from the issue and selected step;
an unknown constraint ID or invalid selector is reported rather than guessed.
JSON output includes context, entries, diagnostics, and a semantic digest for
scoped views.

[Known Constraints](../known-constraints.md) is generated from the registry.
Use `cafe constraints docs render` to render that documentation and
`cafe constraints docs check` from the repository to detect drift. Registry facts
retain their original observed-version and source provenance; publication does
not manufacture a new historical verification date.

## Workflow preparation and publishing fixes

Preparation failures that happen before an agent is invoked can recover through
the existing HumanTask path without inventing a prior CLI/session pair. Legacy
checklist-preparation failures require workflow- and task-bound audit evidence.
Attempts that actually invoked an agent retain the existing exact session
recovery requirements.

The joint-planning checklist treats the previous combined plan as optional, so
first-time `spec_plan` preparation works when no prior plan artifact exists.

Host-owned PR publishing passes the running CAFE interpreter to its script via
`CAFE_PYTHON`. Direct publishing scripts validate Python 3.10+ and PyYAML before
using a local environment or PATH fallback. An invalid explicitly selected
interpreter fails before a push or GitHub mutation rather than silently falling
back to an unrelated project Python.

## Chat accounting fixes

One-shot chat distinguishes missing token accounting from unavailable provider
details. When input and output tokens are recorded but optional model or usage
fields are unavailable, chat reports an informational message instead of an
incomplete-accounting warning. Failed calls and native interactive accounting
retain their incomplete-coverage warnings.

Resumed Codex calls subtract a verified native session baseline from cumulative
token totals, recording only the current invocation's usage. The baseline must
match the exact session and remain intact; missing or ambiguous evidence leaves
token and cost fields unknown instead of attributing earlier usage to the call.
Invocation durations remain available. Requested configuration does not supply
an inferred provider model identity or USD price.

## Upgrade guidance

```bash
pip install --upgrade cafe-engine==0.7.3
```

Interactive phase chat now requires native delivery of the initial constraints
context. Gemini, Copilot, and Cursor interactive adapters do not support that
contract and are rejected before launch. Use one-shot phase chat with `--prompt`
for those providers. Claude and Codex retain their supported interactive context
paths. This also applies to read-only interactive inspection; native read-only
permission restrictions still apply separately.

Existing workflows continue using their selected playbook and confirmation
ownership. Constraints are package-owned; no project-local copy or manual
registry installation is required. Material applicable constraint changes
participate in the existing freshness and resume checks. Use the deliberate
helper-sync path when updating globally installed Manager guidance.

See [v0.7.2 release notes](v0.7.2.md) for execution diagnostics, native Codex
activity detection, and session-persistence behavior retained by this release.

Publishing the GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
