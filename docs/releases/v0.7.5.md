# CAFE v0.7.5 release notes

## Release scope

CAFE v0.7.5 is a patch release integrating the three preserved local recovery
and native skill commits through #595. It fixes legacy preparation recovery and
Git visibility of user-owned native skills, with regression coverage for the
complete recovery-to-publication journey. The base preparation recovery fix was
already shipped in v0.7.3 and is not duplicated.

## Legacy workspace preparation recovery

Older runtimes could stop on a dirty workspace before invoking an agent without
persisting an invocation marker or a provider session identity. The existing
HumanTask fresh-session recovery path now recognizes that specific preparation
failure when audit records correlate the workflow, step, task, and first attempt.
The task-materialization event must follow the matching preparation failure.

Contexts with evidence that an agent was invoked, ambiguous provider identity,
unrelated tasks, or different failure reasons retain their existing rejection
behavior. Recovery does not invent a previous provider session or treat a dirty
workspace as complete; workspace checks remain applicable before execution and
publication can proceed.

## Managed native skill Git exclusions

CAFE writes local Git exclusions for its managed skill manifest and individual
managed native skill directories. It removes only the exact legacy
whole-directory exclusion block previously written by CAFE and preserves
unrelated user rules. Project `.gitignore` files are not changed.

This prevents injected helpers from making a workspace appear dirty when a
project allows its native skill directory, while keeping user-owned skill edits
and new skills visible. Real Git regression tests cover ordinary repositories
and linked worktrees across supported native skill directories. Tracked files
continue following Git's normal change detection.

Recovery journey tests also verify new-session recovery, subsequent correction
in the exact producing session, successful publication, and reconstruction
without repeated external effects in both baton and legacy execution modes.

## Upgrade guidance

```bash
pip install --upgrade cafe-engine==0.7.5
```

The local exclusion migration runs when CAFE writes its managed skill manifest
during skill installation or synchronization. After migration, `git status` may
show user-owned native configuration or skills that CAFE's old whole-directory
rule previously hid; handle those files through your project's normal Git policy.

The [v0.7.3 chat upgrade guidance](v0.7.3.md#upgrade-guidance) remains applicable:
Gemini, Copilot, and Cursor phase chat use one-shot `--prompt` because their
interactive adapters cannot deliver the required initial constraints context.
The runtime and release-check performance improvements documented in
[v0.7.4](v0.7.4.md) are retained.

Publishing the GitHub release triggers the trusted PyPI publisher, which builds
and publishes distributions from the exact release tag.
